# Britto KitCode v2.0

**An AI orchestration template system for Claude Code and Gemini CLI.**

Copy this into any project and instantly get 21 specialist agents, 40 knowledge skills, 13 slash commands, persistent session memory, and automatic rules by file type — all coordinated by a master protocol that works across Claude, Gemini, Cursor, and Copilot.

---

## Why

Every session, Claude starts from zero. Without structure, it acts as a generic assistant. With Britto KitCode, it knows:

- Which specialist to invoke (frontend, backend, security, legacy, etc.)
- Where the last session left off (`.context/PICKUP.md`)
- What was discovered in previous sessions (`.context/PROJECT-MEMORY.md`)
- How to map legacy code before touching it (`/archaeo`)
- How to review its own implementation without bias (`/review`)

---

## Install in 3 steps

**1. Copy into your project root:**

```
your-project/
├── CLAUDE.md          ← entry point for Claude Code
├── GEMINI.md          ← entry point for Gemini CLI
├── AGENTS.md          ← cross-tool standard (any AI)
├── .claude/rules/     ← auto-loaded rules by file type
└── .agent/            ← the full system
```

**2. Create the context folder:**

```bash
mkdir .context
```

**3. Open Claude Code or Gemini CLI in your project root.** The system loads automatically.

## How it works

When you open a session, the AI automatically:

1. Checks for `.context/PICKUP.md` → resumes where the last session left off
2. Classifies your request (QUICK / FULL / ARCHAEOLOGY)
3. Selects the appropriate specialist agent
4. Announces: `🤖 Applying knowledge of @[agent-name]...`
5. Applies the agent's rules + skills

**You don't configure anything.** The system self-selects the right expert for each task.

## Key Concepts

### Startup Modes

| Mode | Triggered by | Loads |
|---|---|---|
| **QUICK** | Simple questions, small fixes | `CORE.md` only |
| **FULL** | Build / implement / refactor | `CORE.md` + architecture + active plan |
| **ARCHAEOLOGY** | Legacy code | `CORE.md` + project memory + legacy map |

### Session Files (in `.context/`)

| File | Purpose |
|---|---|
| `PICKUP.md` | Handoff — where last session stopped, next exact step |
| `PROJECT-MEMORY.md` | Persistent memory — traps, decisions, confirmed stack |
| `ARCHAEOLOGY.md` | Legacy code map — generated by `/archaeo`, persists forever |
| `{task-slug}.md` | Task plan — generated by `/plan`, tracks progress |
| `{task-slug}-spec.md` | Spec — defines WHAT before HOW (Spec-Driven Development) |

### Auto Rules by File Type

| You edit | Rules auto-loaded |
|---|---|
| `*.sql`, `*.prisma` | SQL security, migration rollbacks, N+1 prevention |
| `*.test.*`, `*.spec.*` | Test structure, AAA pattern, mock guidelines |
| `*.css`, `*.scss` | Mobile-first, 8pt grid, WCAG accessibility |
| `route.ts`, `controller.*` | API validation, auth/authz, status codes |
| `/legacy/`, `/old/` | Map before modify, minimum intervention, archaeology workflow |

### Writer/Reviewer Protocol

For complex tasks: one session implements (Writer), a separate clean session reviews against the spec without implementation context (Reviewer). This eliminates confirmation bias and catches what the writer can't see.

## UI/UX System

The `/ui-ux-pro-max` command activates a full design system with:

- 50+ UI styles categorized
- 21 color palette recommendations by product type
- Font pairing reference
- 100+ Lucide React icons indexed by category
- UX guidelines and web interface best practices
- Stack-specific guidelines: Next.js, React, Vue, Svelte, Flutter, SwiftUI, React Native, and more

All data stored as indexed Markdown — the AI reads only the relevant section, not the full file.
